Bunny Arcade

Ten pixel-art games built on a small engine I wrote. The game logic is deterministic and seeded, kept apart from rendering, and tested in Node on every push. No framework and no dependencies.

10 games0 dependenciesTested in CI

The problem

I wanted the portfolio to be memorable, so the bunny from the banners got its own games. But I didn't want a pile of throwaway scripts. The goal was to build them the way I build backend services: small pure units with clear boundaries, deterministic behaviour that tests can pin down, and nothing that needs a framework, a build step or a dependency to run.

What I built

  • A shared engine (play/kit.js): one mount() runs any game definition. It owns the frame loop (clamped, never-negative time steps), input from keyboard, touch zones, drags and swipes, best scores, pausing when the game is off-screen or the tab is hidden, and a self-play mode. Each game is a plugin that calls Arcade.register().
  • A pure, deterministic core: every game's rules are a state machine, create(seed) then step(dt, input), returning events. The random numbers are seeded, so any run can be replayed exactly. The rules never touch the DOM: the same split between domain logic and I/O that I use in backend services.
  • Event-driven edges: the logic emits events such as stomp, catch and over. The scoreboard, best-score storage, visual effects and screen-reader announcements all subscribe to them instead of being wired into the rules.
  • Platformer physics for Bunny Quest: fixed 8 ms sub-steps so nothing tunnels through a tile on a slow device, separate X and Y collision passes, coyote time, jump buffering and variable jump height.
  • Bots that double as tests: every game ships a self-playing bot that drives the live previews. The same bots are test oracles: CI checks that the Bunny Quest bot can finish all three levels, so a level change that makes the game unbeatable fails the build.
  • Accessible and light: keyboard-first controls, screen-reader status messages, reduced-motion support, and games that stop drawing when nobody can see them.
  • Day and night: a shared sky module draws the sunset, moon and stars behind every banner with canvas compositing, in step with a CSS dark-mode transition. Click the sun in the banner above.

Results

  • Ten games, from a three-level platformer to a deploy-pipeline timing game, in about 2,400 lines of plain JavaScript.
  • 26 tests covering rules, physics, scoring and the bots, run with Node's built-in test runner on every push through GitHub Actions, in under a second.
  • No dependencies, no build step: the site is static files from any host.
